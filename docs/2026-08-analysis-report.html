HACCP 17개 제품 — 현황과 개선 제안

확인 필요: 5개 자료 어디에도 17개 제품의 전체 목록·SKU·규격은 없습니다. 확인된 것은 파일럿 상품 "이천쌀 떡볶이"(피치덱)와 PB 전략상품 "프리미엄 떡볶이·어묵탕"(인포그래픽) 뿐입니다. 아래는 이 구조를 17개로 확장한다는 전제 하의 개선 제안입니다.

01 · 데이터 표준화

17개 SKU를 표준 스펙 시트로 통일

제품명·카테고리·HACCP 인증번호·원산지·유통기한·패키징 규격·MOQ·타겟국가 8개 필드로 통일하면, 세움 AI가 바이어 문의에 즉시 견적을 매칭할 수 있습니다.

02 · 우선순위 압축

17개 중 "First 3" 먼저 확정

온길.cloud 홈에 노출할 대표 3개 제품(현재 떡볶이·어묵탕 확정, 3번째 미정)을 우선 확정해야 COEX 데모 스토리가 완성됩니다.

03 · HMR 규격 확장

피치덱의 3분류(볶음밥용/찌개용/샤부샤부용) 적용

17개 제품을 피치덱이 제시한 목적별 소포장 분류에 맞춰 재배열하면, 신규 파트너 온보딩 시에도 같은 분류 체계를 재사용할 수 있습니다.

04 · 유통망 연계

트레이더스 입점 데이터를 신뢰 증거로 활용

17개 중 이미 트레이더스(이마트)에 입점한 제품이 있다면 사이트·데모에서 "국내 검증 완료" 배지로 노출해 해외 바이어 신뢰를 높일 수 있습니다.

08

구축한 사이트 구조 (ongil.cloud)

신규 파트너가 온길 플랫폼으로 수출을 시작하면, 로고와 대표 제품 3개만으로 아래 구조가 자동 생성되도록 3개 페이지를 실제로 구현했습니다.

ongil.cloud/
├─ index.html — "Here" 메인 랜딩. 문제·해결·워크플로우·로드맵·파트너 로고월
├─ demo.html — 세움 AI 라이브 데모 (명함분석·다국어메일·페이지생성·매칭, 실제 작동)
├─ onboarding.html — 파트너 온보딩 4단계 + 새움 실사례 카드
├─ brands/
│  └─ saeum.html — 새움·삼시먹거리 개별 브랜드 홈 (실사례)
│  └─ [partner-slug].html — 파트너 추가 시 동일 템플릿 반복
└─ docs/
    └─ 2026-08-analysis-report.html — 본 보고서
  • index.html — COEX 참석자가 처음 만나는 페이지. "가격 경쟁의 한계 → 세움 AI 4단계 → 로드맵 → 파트너 로고월" 순서로 5분 안에 사업의 매력을 전달하도록 설계했습니다.
  • onboarding.html — "계약 → 에셋 업로드 → AI 자동 생성 → 발행" 4단계 다이어그램과, 새움을 예시로 한 실제 파트너 카드를 함께 보여줘 신규 파트너 유치 미팅에서 바로 시연 가능합니다.
  • brands/saeum.html — 파트너가 늘어날 때마다 같은 틀로 복제할 단일 브랜드 홈페이지 표준안입니다.

호칭 불일치

정성열 "부장" vs "본부장", 김정석 3개 직급

대외 자료를 통일하지 않으면 COEX 부스에서 명함·발표자료 간 신뢰도가 떨어질 수 있습니다. 최종 호칭 1개로 확정 필요.

확인 필요

ongil.vercel.app / ongil.cloud 현재 상태

이번 세션 네트워크 정책상 직접 접속이 차단되어 현재 사이트 유무를 확인하지 못했습니다. 기존 사이트가 있다면 스크린샷이나 소스를 공유해 주시면 이번 구조와 병합하겠습니다.
